03사람이 내린 결정

AI가 장단점을 정리해 오면, 사용자(학생)와 비용을 기준으로 제가 골랐습니다.

기호 계산 엔진

서버 API · 직접 구현 · 브라우저 내 SymPy
Pyodide + SymPy, 앱에 내장

서버 비용 없이 오프라인에서도 적분·인수분해가 동작합니다. 앱스토어 규정에 맞춰 런타임 다운로드 대신 번들로 넣었습니다.

손글씨 · 사진 인식

클라우드 API · 학습 모델 · 기기 내 규칙 기반
기기에서만 인식, 업로드 없음

사용자가 미성년 학생일 수 있어 이미지를 외부로 보내지 않는 쪽을 택했습니다. 인식이 부족하면 대안을 미결정 항목으로 남겨 두었습니다.

수능 스타일 도형

일반 그래프 내보내기 · 시험지 스타일 모드
흑백·세리프·원점 O 표기

국내 교사와 학생이 바로 쓸 수 있도록 시험지 서식을 기능으로 정의했습니다. 기출 문제는 복제하지 않고 원본 도형만 만듭니다.

“민감하지 않은 건 묻지 말 것”으로 반복 확인을 줄이고, 계정·배포 같은 일만 직접 승인
근거 있는 완료
테스트 결과와 실제 화면 캡처가 있어야 단계 완료로 인정, PLAN.md에 완료·미완료를 기록

05배운 점

  1. 범위를 쪼개면 AI의 결과가 안정된다

    16개 단계로 나누고 한 번에 한 단계만 열자, 큰 코드베이스에서도 테스트가 깨지지 않은 채로 기능이 쌓였습니다.

  2. 가장 좋은 요구사항은 직접 써 본 경험에서 나온다

    계획서에 없던 실행 취소, LaTeX 단축 입력, ≠ 결과의 참/거짓 표시는 모두 제가 써 보다 막힌 지점에서 나왔습니다.

  3. 판단은 위임하지 않는다

    개인정보, 비용, 대상 사용자처럼 제품의 성격을 정하는 선택은 AI가 정리한 선택지를 보고 제가 결정했습니다.
